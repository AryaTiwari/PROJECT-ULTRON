# Mark 3 capability migration into Mark 4

Mark 4 keeps Hermes as its cognitive foundation. Mark 3 contributes proven domain behavior, contracts, schemas and regression cases. Mark 4 does not start Mark 3 processes or import the old orchestration layer.

| Mark 3 capability | Mark 4 implementation | User-visible surface |
| --- | --- | --- |
| Identity, memory and context continuity | `SOUL.md`, `USER.md`, durable `MEMORY.md`, Hermes sessions and mission evidence | Command, Missions, session drawer |
| Planner, operator and Forge execution | Hermes cognition plus durable Mark 4 missions, event stream and capability host | Missions, execution trace, Operations |
| Direct model routing and fallback recovery | Gemini aliases, Grok/xAI, NVIDIA, Groq compatibility, then keyless Big Pickle | Runtime model route and error card |
| Adaptive web research | Hermes browser/web tools with the `adaptive-research` skill and evidence boundaries | Command trace and mission evidence |
| LinkedIn company and job discovery | Native lead registry, LinkedIn capability contracts and `linkedin-company-research` skill | Command and Lead Master command |
| Apollo company/contact work | Native Apollo capability with one-run paid approval, verified top decision makers and India-number preference | Approval card and lead workspace commands |
| Google Sheets delivery | Native Workspace wrapper, gid/title worksheet resolution and source-aware fields | Google status and delivery commands |
| Creator intelligence | Canonical creator registry, evidence requirements and `creator-operations` skill | Creator Registry command |

## Native migration rules

1. Keep Mark 4 reasoning, missions, sessions and tool events authoritative.
2. Port contracts and evidence rules before implementation details.
3. Never fabricate rows, contacts, metrics, sources or completion.
4. Read-only and reversible work proceeds autonomously. Paid APIs, external messages and publishing use explicit approval.
5. Persist checkpoints and evidence so a mission can resume without repeating paid or account-sensitive work.
6. Keep discovery separate from contact enrichment unless the user asks for both.
7. Treat the canonical registries as the source of truth for deduplication and progress.
8. Do not start Mark 3 services from the Mark 4 runtime.
